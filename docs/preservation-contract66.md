# Document preservation contract66

This contract applies to future consumers of the reusable engine as well as the
new workbench. Package validity, editable structure, original appearance, native
save preservation and current-data acceptance are separate results. Neither
`reportReady` nor `supervisorAccepted` is promoted by a successful local test.

## What the new local boundary verifies

Original imports are content-addressed immutable assets. Report profiles,
evidence, generated candidates and portable recovery bundles retain their own
identities and hashes. Outputs use new paths; a generated result does not replace
the imported source. A recovered analysis/review is historical context and needs
fresh source analysis and review before a draft can be generated. The host checks
the current persisted actor, project, source/evidence bindings and role again.
Fixed labels and explicit historical comparisons are distinct from measurements
and judgments for the current period. No missing current facts are invented.

Both native and hybrid package guards reject duplicate or unsafe ZIP entries,
bounded-size violations and inconsistent recovery hashes/links. These checks do
not prove font selection, row semantics, page fidelity or every object's native
editability. See the named tests in FINAL66 and the frozen shared golden inputs.

## Native Hancom save is a separate boundary

Inherited supervisor reviews59/61/62/63 established that automatic picture
downsampling on save affected the earlier final28 copies. With that save option
disabled in the supervisor-owned tests, all52 Seonam and627 Daecheong picture
bytes/dimensions/pixels and the20/31-page before/after output were retained. This
is evidence for those exact old copies and settings, not a native test of the
new .NET package or permission to change settings. No density/imgDim workaround,
image deletion or arbitrary reduction is introduced here.

Those reviews separately left original font use/embedded-font retention,
`jindan-source.json` loss and three changed tab attributes unresolved. A font's
name or embedded flag is not proof of native selection or save retention.
Native-save output must be compared by exact SHA and actual resolved output;
the workbench does not install fonts or modify Hancom configuration. Do not
serialize invented options or overwrite company document metadata to suggest
that these native-save limitations have been solved.

Project identity, original assets, binding context, review/evidence and generated
files must therefore also remain in the project/recovery archive. An arbitrary
HWPX saved in another application is not a substitute for that archive. A valid
return requires the expected source/context/slot identities and fresh bindings;
missing or stale state fails closed. Preservation of JDF slot names in an older
selected48-cell test does not authorize all company forms or all returned files.

## Acceptance and consumer obligations

Record input/output SHA, source package/runtime, scope and actual verification
method. Reopen/edit/save/native-PDF comparisons belong to the exact file tested.
Do not transfer a prior candidate's acceptance to a new SHA, interpret a
programmatic acknowledgement as a human review, or label historical values as
current measurements. Live cloud services, all-object editing, all company data
and complete real current-period workflows remain separate acceptance gates.

The old supervisor records and frozen packages stay read-only. ROADMAP66 adds a
local modular implementation and reproducible checks; it does not rewrite those
records or claim that the inherited native limitations are resolved.

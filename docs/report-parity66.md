# Report module parity66

The native report workbench uses C# contracts, a separately replaceable module
DLL, local asset storage and an owned-process adapter. Existing report algorithms
remain one repaired JavaScript source behind the versioned Node worker. This is
hybrid migration, not a claim of complete pure-C# layout-engine replacement.
`reportReady=false` and `supervisorAccepted=false` remain mandatory.

The machine-readable11-group matrix and source hashes are in
`migration/report-parity66.json`. The earlier28-group static inventory remains
unchanged in `migration/feature-inventory66.json`; inventory alone was never an
implementation claim. The active old entry was `src/App.jsx`, and the exported
ReportStudio was ReportPlatform; the separate discipline workspace was also
active and is represented here.

The formatting inspector edits source-derived page size/margins, role fonts,
character width/spacing, paragraph indents/spacing/break flags, furniture text
slots/alignment, original-object placement and actual local image replacements.
Its output is a separate formatting candidate retaining historical content. It
does not bypass the strict current/blank draft review pipeline. Native page
location uses actual independent-renderer text-layout runs, including text boxes;
multiple matches are listed as candidates. PDF uses exact source-page anchors.

Legacy project import uses the existing pure archive reader, not the old
IndexedDB mutation importer. It verifies every file and cross-reference, previews
the exact archive SHA/counts, requires explicit confirmation and checks the
archive/sidecars again before asset import. Old IDs map to current-project local
IDs (existing identical local assets may deduplicate). Old chapter text/settings
become read-only historical context. Actors, permissions, executable analyses,
reviews, acknowledgments and old current field values are not adopted. Imported
measurement files are labeled historical and excluded from current-draft evidence
and electrical current links. Fresh source analysis/review is required.

Reproduction commands, runtime/package dependencies, actual protocol limits and
native control names are documented in `docs/report-adapter66.md` and
`docs/worker-protocol66.md`. Native UI evidence uses a new owned STA WinForms
test with real local storage/adapter/worker and isolated synthetic files, not
other applications or Hancom. Exact latest counts and hashes in the JSON/logs
must be refreshed after the final run; old pass counts are not silently inherited.

Final local guards cover new-only/no-replace exports, protected/UNC/reparse
destinations, per-project profile optimistic SHA and owned exclusive lease,
16MiB/corrupt-profile fail-closed loading, dirty-context preservation, scoped
existing-asset/viewer reads, and owned-process shutdown drain. Portable recovery
retains the full native workstate as read-only historical context and makes
recovered evidence/candidate copies accessible without adopting old approval.
The source checks passed20 worker tests,41 adapter checks and53 actual synthetic
native UI checks. Separate actual final66-r6 package validation passed60/60:
the same53 flow checks plus6 loaded-DLL hash comparisons and bundled runtime
presence. The receipt records exact assembly/runtime/worker hashes and paths.
This local synthetic package evidence does not approve real company/native
report layout or current measurement data. Earlier exact R2/R4 evidence remains
unchanged and separate; fresh R6 output is artifacts/report-ui66-packaged-r6.
R3/R5 Report GUI was held before execution and has no inferred pass. REVIEW69's
updater full-data snapshot contract is distinct from the report historical

whole numerical/cell semantics, every object edit and real company current-data

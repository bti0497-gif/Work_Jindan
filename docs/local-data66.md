# Local data/domain66

`new Jindan.Infrastructure.LocalWorkspace(absoluteDataRoot)` implements the unchanged contracts `IWorkspaceData`, `IIdentityService`, `IAssetService`, `ILayoutStore`; `Jindan.Core` and `Jindan.Infrastructure` target plain net10.0 with BCL-only dependencies and no UI references. Register module `RecordSchema`s before writing/importing their kinds. Existing authorized records remain readable when an optional feature schema/DLL is absent; unknown-kind writes still fail closed. Root records use `projects` (or legacy singular `project`) with ProjectScoped=false. Child schemas use ProjectScoped=true. Dates use yyyy-MM-dd; startDate/endDate ordering, required fields, choice/number fields and unknown keys are checked in Core.

Bootstrap is an explicit new-local-workspace action, requires a user-chosen display name/password and `explicitLocalWorkspace=true`; there is no default administrator or live authentication bypass. Passwords require10+ characters and use random32-byte salt/PBKDF2-SHA256210,000 iterations/fixed-time verification. Authenticated Identity instances are private reference-bound sessions, not trusted DTO claims: manually constructing/cloning an administrator Identity fails. Every service resolves the persisted user again, so changed membership/disabled state/role take effect in existing sessions. Roles: admin/editor/viewer. Session identities are not persisted or exportable and must be logged in again after restart. These are local workspace identities, not corporate cloud roles.

Authorization: administrators access all records; project children require active parent and membership; editors may write within assigned projects; viewers never write. Project creation/deletion is admin-only. Personal nonproject records/tasks require ownership; explicitly isPublic=true tasks may be read by other authenticated local users, but only the task owner/admin may write or delete them. Board reads allow all authenticated local users; only author/admin may change a post. Member administration and import/rollback are administrator-only; the active administrator cannot disable their own session account and the last enabled administrator cannot be demoted/disabled. relatedProjectId and assetId/*AssetId references are checked against project scope. Data deletion is logical and requires explicit confirmation and current revision; no original assets are deleted.

`workspace.json` uses schema1 and optimistic record revisions. Each operation takes an exclusive workspace.lock file lease, reloads the store, works on a clone, writes/flushed a unique temp file, then atomically replaces the primary with backup. Thus separate workspace instances cannot overwrite stale revisions. Locked-file failures leave committed state unchanged and clean temp files. Startup malformed primary recovery preserves a uniquely named corrupt file and restores a valid backup. Future schemas are blocked rather than downgraded or silently replaced by an old backup. Layout persists as part of that local store. The store/backup/rollback include local password hashes; never export them or include these files in public artifacts/logs.

Asset import copies source bytes into a SHA256-addressed original blob, returns project-scoped metadata and deduplicates identical content within a project. It never writes source files. Get/export verify stored size/hash; source/stored link paths are rejected. Copies/cancellation/locked input failures are bounded; assets max256MiB. StoredPath is an original: modules must treat it read-only and create separate edits. Asset service is format-neutral; photo modules must decode/validate image content for preview rather than treating extension-derived MediaType as a valid-image claim. Damaged assets are detected by content hash, not automatically replaced. Orphan hash blobs after cancelled/failed metadata commit may remain for safe later maintenance; no automatic destructive sweep is performed.

Workspace export is a bounded ZIP of data.json plus referenced hash assets, never identity/password/session/layout stores. Import preview verifies source SHA, schema/registered fields/parent relationships, entry paths/duplicates/count/expanded size and every asset hash. Confirmation revalidates exact bytes and imports only new record/project/asset IDs with known ID fields remapped. Originals/existing records remain. Rollback snapshots are local and version-bound: rollback refuses after any subsequent committed mutation, preserving newer work; content blobs remain deduplicated. Limits:10,000 records/entries,16MiB manifest,256MiB archive,512MiB expanded. These packages provide integrity, not publisher authentication.

F:/jindan and F:/jindan-maintenance are forbidden as data roots or export destinations; E:/jindan backup is also forbidden for export. Exports require new absolute local paths, reject UNC/alternate streams, stage only owned temporary files and never replace/delete a racing existing destination. Reparse-point workspace parents/assets/data files are rejected. This is a local application policy, not a sandbox against an administrator racing arbitrary filesystem mutations. Production databases/cloud/user credentials are neither read nor changed. Tests use only newly created synthetic artifacts/domain-tests folders and preserve test evidence. No forced process termination, security setting changes or corporate data migration occurs.

Run from the new root with explicit local SDK; process-local SDK environment must include DOTNET_GENERATE_ASPNET_CERTIFICATE=false, DOTNET_CLI_TELEMETRY_OPTOUT=1, DOTNET_SKIP_FIRST_TIME_EXPERIENCE=1, DOTNET_NOLOGO=1 and DOTNET_CLI_HOME=F:/jindan-dotnet/.tools/cli-home:

```powershell
& ./.tools/dotnet/dotnet.exe run --project tests/Jindan.Domain.Tests/Jindan.Domain.Tests.csproj --no-launch-profile
```

The console suite fails via exit1 and prints per-scenario counts. It covers real filesystem persistence/restart, ACL negatives, atomic/lease faults, asset hashes/locks/cancellation, new-copy ZIP/rollback and corruption/future schema gates. Tests do not claim Hancom, cloud integration, original font preservation or company current-report approval; reportReady=false and supervisorAccepted=false remain.

# 메뉴바·DLL 사이드바 구성 — 2026-11-09

## 사용자 결정

앱 제목줄 아래에는 업무 메뉴바 한 줄만 둔다. 별도 프로젝트 선택줄,
업무 선택 툴바, 열린 문서 탭줄과 MDI 자식창 아이콘/창 버튼을 표시하지 않는다.
프로젝트, 파일관리, 할일관리, 보고서 스튜디오, 게시판, 회원관리, 설정으로
구성한다. 회원관리는 관리자에게만 표시한다.

프로젝트 메뉴의 왼쪽 사이드바에 프로젝트관리·공정관리와 현재 프로젝트
콤보박스를 표시한다. 다른 기능도 같은 공통 틀에 해당 DLL의 메뉴와
검색·목록 패널을 제공한다. 스튜디오는 전용 화면을 유지하고 프로젝트
선택 및 ‘업무 화면으로’ 복귀를 왼쪽에 둔다.

이 결정은 architecture66.md의 과거 문서 탭/상단 선택줄 구성을 대체한다.
메인폼은 공통 연결을 맡고 기능 DLL이 화면과 메뉴를 제공하는 원칙은 유지한다.

## 구현

- `IModuleNavigation73`: 기능 DLL이 메뉴 그룹과 사이드바 경로를 선언한다.
  Projects/Processes는 같은 프로젝트 그룹을 선언한다. 모듈 간 DLL 참조 없이
  식별자로 이동 요청을 전달한다.
- `WorkspaceSidebar73`: `Jindan.Desktop.Contracts.dll`의 재사용 컨트롤.
  기능 DLL이 제공한 패널과 경로를 구성한다. 새 사이드바 전용 어셈블리를
  추가한 것은 아니다.
- 메인폼은 선언으로 한 개의 메뉴바를 만들고 활성 문서의 사이드바를 연결한다.
  프로젝트 변경이 미저장 검사에서 거부되면 콤보박스도 원래 선택으로 되돌린다.
- 같은 메뉴/프로젝트의 문서를 재사용한다. 내부 문서 컨텍스트·저장·닫기
  처리는 유지하며 상부 탭을 추가하지 않는다.
- 자식창 아이콘과 창 버튼을 표시하지 않는다. 스튜디오 진입 시 뒤의 최대화
  자식창을 복원해 제목줄에 이전 업무명이 붙는 문제도 없앴다.
- `sidebar-navigation/73` 호스트 요구사항으로 구형 호스트에 새 패키지를
  적용하지 못하게 한다. 이번에는 호스트와 공통 UI DLL을 함께 교체해야 한다.

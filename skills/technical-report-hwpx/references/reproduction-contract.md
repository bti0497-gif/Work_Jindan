# 작성·재현 계약

## 원본과 후보

원본 HWPX와 대응 PDF를 보존한다. 같은 파일명이어도 해시가 다르면 서로 다른 버전이다. PDF 페이지만 있고 HWPX 원본이 없는 부분은 편집 가능한 원본의 부재를 표시한다. 한 파일에 여러 장이 있거나 한 장이 여러 파일로 나뉠 수 있다. PDF의 파일 내 페이지와 책 전체에서의 쪽 번호를 따로 기록한다.

분석 결과에는 `source.sha256`, 파일 상대 경로, 구역과 문단/셀/글자 구간 근거가 있어야 한다. 보고서 간 서식의 동등성은 스타일 ID가 아니라 실제 글꼴·크기·문단 속성·배치로 판단한다. 전체 본문이나 과거 판정 데이터를 스킬 지침·공개 테스트 자료에 넣지 않는다.

## 편집 가능한 작성본

HWPX 원본이 있으면 원본 패키지를 보존하고 확인한 글자 구간에 새 내용을 넣는다. PDF만 있는 경우에는 `pdfAnalysis.js`/`pdfStructure.js`로 쪽·문장 좌표와 표 선/병합 후보를 추출하고, `pdfOcr.js`로 이미지 본문을 로컬 인식한 뒤 `pdfHwpxWriter.js`로 새 패키지를 만든다. 전회 참고본은 과거 값이 포함된 재구성본이며, 금회 작성 양식은 검토한 항목 열·표 첫 행·제목만 유지하고 측정값·판정·진단 문장과 사진 자리를 비운다. 본문·표는 편집 가능한 개체이며, 원문 그림은 해당 그림 영역만 추출한다. OCR 값으로 이미 해독된 PDF 표 수치를 덮어쓰지 않는다. PDF 쪽/좌표·원본 SHA·프로젝트를 작성 이력과 패키지 내부 근거 JSON에 남긴다. 재구성본은 글꼴·페이지 조판의 동일 재현 완료를 뜻하지 않는다. `write-candidate.mjs`는 `sourceSha256`과 모든 `expectedText`가 일치할 때만 교체한다. 새 내용은 XML로 이스케이프하고, 지정하지 않은 바이너리·서식 부분을 보존한다. 그림만 붙인 PDF를 HWPX 작성본으로 대신하지 않는다.

`--slots` 결과는 실제 입력 위치를 지정하는 작업 자료다. 보고서 전체의 글자 구간이므로 필요한 문단·셀만 고른다. 분석에 나타났다는 이유만으로 모든 슬롯을 일괄 비우거나 과거 내용을 새 값으로 확정하지 않는다.

```json
{
  "sourceSha256": "분석 결과의 원본 해시",
  "replacements": [
    {"slotId": "분석 결과의 editableSlots에서 선택", "expectedText": "해당 구간의 기존 글자", "value": "이번 보고서의 새 글자"}
  ]
}
```

수정이 다수의 글자 모양 구간이나 복합 개체를 가로지르면 자동으로 합치지 않는다. 문단·셀 단위 바인딩이 필요한 경우 앱의 `nativeWriter`/`nativeCollection` 경로를 사용한다. 원본의 한 쪽만 골라 재현하려는 경우에는 한 쪽에 포함되는 본문·표·그림·공유 스타일·머리말·꼬리말과 자산 의존성을 확보한다. 구역 하나가 한 페이지라는 가정으로 XML을 잘라내지 않는다.

## 빈 점검표와 회수

왼쪽 목록·항목명·단위·병합 셀은 보존한다. 오른쪽의 명시적으로 지정한 판정·입력 셀만 비운다. 내보낼 때 원본 해시와 표 ID, 셀 ID, 행/열 좌표 및 범위를 기록한다. 회수 문서의 원본 바인딩과 구조를 확인해 정확히 같은 셀에 넣는다. 이름이나 텍스트 유사도만으로 다른 표에 덮어쓰지 않는다. 변경·충돌·미입력은 검토 목록으로 남긴다.

## PDF 대조

후보 PDF는 후보 HWPX나 실제 편집 모델에서 내보낸 결과여야 한다. 원본과 후보를 같은 DPI로 렌더링하고 다음을 함께 확인한다.

- 용지 크기, 재단/출력 여백, 구역별 A4/A3 및 방향
- 글꼴 대체, 크기, 굵기, 행간, 줄바꿈, 들여쓰기, 셀 병합과 높이
- 표·그림·도형 위치, 캡션, 계속 표, 본문 참조와 차례
- 표지·속표지·장 구분 표지·본문·빈 쪽·책등의 역할
- 앞부분 로마숫자와 본문 숫자 쪽 번호, 홀짝 시작, 빈 쪽의 머리말·꼬리말·번호 숨김
- 내용 변경 시 줄 수와 쪽 수가 늘어나는 경우의 재조판

비교 스크립트는 나란히 보기와 차이 그림, 용지·텍스트·화상 차이 지표를 만든다. 서로 같은 원본 바이트의 대조나 편집 원본이 없는 대조는 재현 검증의 증거가 될 수 없다고 표시한다. 수치가 작더라도 변경돼야 하는 문구·표 셀을 확인한다. 글꼴 렌더링 차이로 생긴 작은 차이와 표의 누락·잘림을 구분하고, 임의의 단일 점수만으로 합격을 선언하지 않는다.

## 확정 범위

검증 상태는 단계별로 기록한다: `extracted` → `candidate-generated` → `compared` → `verified`. 알려진 누락이 있으면 `partial` 또는 검토 필요 상태를 유지한다. 특정 대표 페이지를 검증했으면 그 페이지와 구성 요소 범위만 보고한다. 다른 보고서의 긴 본문·다른 표·다른 장 순서·A3 구역을 별도로 통과하기 전에는 범용 재현 완료라고 말하지 않는다.

# 프로젝트 보고서 작업 흐름

사용자와 2026-11-03에 합의한 화면이다. PDF·HWPX 원본 쌍의 별도 학습 시험에 앞서 이 플랫폼 안에서 분석·한글화·비교를 수행하고 엔진을 개선한다.

## 분석 목적과 단계

PDF는 먼저 `purpose: restoration`인 **PDF 복원 분석**을 수행하고 선택한 장의 한글화 후보를 생성한다. 생성 직후 실제 HWPX 바이트를 다시 읽어 `purpose: authoring`인 **새 보고서 작성 분석**을 별도 단계로 저장한다. 원래 한글 전회 보고서는 바로 작성 분석을 수행한다. 복원 분석의 결과를 작성 분석으로 복사하지 않으며 실제 재현 검증의 완료로 취급하지 않는다. `report-workflow/2` 이후 이 목적을 구분한다. 이전 버전은 원본을 보존한 채 다시 분석한다.

PDF 분석 직후에는 장 카드가 선택되지 않는다. 카드를 누르면 해당 장이 선택되고 같은 카드를 다시 누르면 선택을 해제한다. 한글보고서화는 현재 원본·프로젝트의 유효한 복원 분석과 선택한 장이 있을 때만 활성화한다. `chapterConversion.js`가 장의 원본 페이지(공백·장 표지 포함)와 소유 관계를 검증하며 수동 전체 쪽 설정으로 범위를 넓히지 않는다. 오른쪽 쪽 포함 표시는 장 선택을 따르는 읽기 전용이며 수동 범위 입력은 이전 호환 화면에서만 유지한다. 한 장이 300쪽을 넘으면 범위를 검토하도록 알린다.

장 제목이 포함된 별도 HWPX를 목록에 등록하고 `reportMetadata.chapterSource`·`pdfWritingRuns` 및 패키지 `Contents/jindan-source.json`에 원본 ID·SHA·장 ID·제목·원본 페이지를 기록한다. 목록에서 생성본을 열면 해당 HWPX 자체의 미리보기와 작성 분석을 바로 볼 수 있다. PDF 원본 페이지 범위와 한글 렌더러의 페이지 번호를 구분하며 PDF 쪽 수를 한글 쪽 수로 대입하지 않는다.

중앙의 기본 전환은 **미리보기 / 분석보기**이다. 분석보기의 처음 화면은 챕터별 요약이며 표·그림·머리말·꼬리말·본문 문단/페이지·장/중간 제목과 역할별 서체를 보여준다. PDF 글자 이미지 조각을 그림 개수에 섞지 않고, 머리말 표를 본문 표와 분리한다. 실제 쪽 수를 모르는 HWPX에서 명시적 나눔 수를 쪽 수로 표시하지 않는다.

챕터 선택은 오른쪽 `ReportChapterInspector`에 연결한다. 챕터 이름·분야·메모는 원문을 바꾸지 않는 분석 보정이다. 글자 서식 후보는 `typographyScope`의 원본 구역·문단 인덱스와 SHA를 검증하고 선택한 챕터의 본문·제목·표 글자만 복제 서식으로 변경한다. 공유 머리말과 인접 챕터는 유지한다. 용지·여백·머리말·꼬리말은 별도 ‘구역 공통 서식’이며 하나의 구역이 여러 챕터에 걸칠 수 있음을 표시한다.

PDF를 선택하면 PDF 원본, HWP/HWPX를 선택하면 그 한글 파일 자체를 표시한다. 연결 원본 PDF를 한글 미리보기로 대신하지 않는다. `NativeReportPreview` → `nativePreview.js` → 별도 `nativePreview.worker.js`가 선택 파일 ID로 읽은 바이트의 SHA를 검증하고 `@rhwp/core@0.8.7`로 용지·글꼴·표·그림·머리말/꼬리말과 페이지를 조판한다. 로컬 WASM과 시스템 글꼴을 사용하며 외부 문서 업로드·CDN·COM을 쓰지 않는다. 페이지는 안전한 SVG 이미지로 표시하고 화면 근처 페이지만 생성·유지한다. 페이지 수와 줄바꿈은 이 렌더러의 결과이며 한컴 프로그램 출력과 완전히 같다고 확정하지 않는다. 렌더링 실패 시 PDF로 대체하지 않고 오류를 표시한다.

중앙에는 미리보기/분석보기만 두고 별도의 ‘원문 PDF 대조’ 버튼·연결 원문 표시·대조 전환 화면을 두지 않는다. 대응 PDF 연결은 오른쪽 ‘학습용 원본 PDF’로 관리하는 출처·학습 메타데이터다. 한글 페이지는 `nativePreviewPage`로 PDF 페이지와 별도로 저장한다. 원문 위치를 확인하는 기존 구조 뷰는 분석 상세에서만 ‘추출 구조’로 표시한다. 추출 웹 문단을 한글 페이지처럼 표시하는 옛 `ReportDocumentView`를 기본 미리보기로 다시 연결하지 않는다.

표·그림·문단의 ‘원문 위치 보기’는 임시 이동이다. PDF는 분석 원본의 페이지와 bounding box를 이용해 해당 영역으로 스크롤하고 표시한다. 한글은 원본 표/셀·문단 ID 또는 그림 개체 ID로 `ReportSourceLocation`을 열고 주변 문맥과 실제 원본 자산을 보여준다. 모르는 한글 쪽 번호를 만들어 붙이지 않는다. 한글 표의 셀 선택과 기존 금회 자료 반영 경로는 유지한다.

원문으로 이동하면 중앙 작업 영역에 ‘분석으로 돌아가기’ 버튼을 띄운다. 분석 목록과 챕터 편집기를 재생성하지 않고 숨겨 유지한다. 돌아갈 때 관리 탭, 챕터 필터, 펼친 그림, 좌우 스크롤 위치, 챕터 서식 대상과 원문 보기 버튼의 키보드 초점을 복원한다. 이동 근거는 보고서 ID·SHA에 묶고 다른 보고서나 프로젝트에서는 이전 돌아가기 버튼을 노출하지 않는다. 이 기능을 별도의 PDF 대조 메뉴로 확대하지 않는다.

## 화면 역할

- 왼쪽 맨 위에서 현재 작업 프로젝트를 선택한다. 프로젝트 목록은 기존 프로젝트 관리의 갱신 이벤트를 따르며 수동 새로고침 버튼을 두지 않는다. 보고서·자료·설정은 프로젝트와 로그인 사용자에 귀속한다.
- 왼쪽 전회 보고서 가져오기는 드라이브·일반 파일 아이콘과 툴팁을 사용한다. 그 아래 리스트뷰에서 선택한 보고서를 중앙에 연다. 분야와 장·범위는 보고서별 정보이며 장 번호로 분야를 고정하지 않는다.
- 보고서 행 오른쪽 휴지통은 확인 후 현재 프로젝트 목록에서만 제거한다. 원본 파일·분석·생성 이력은 보관하며 다른 프로젝트의 목록은 바꾸지 않는다. 선택한 생성본을 제거하면 목록에 남은 원본으로 돌아가고, 마지막 보고서를 제거하면 빈 작업 영역을 보여준다. `removedReportIds`로 재진입 시 자동 재등록을 막고 금회 자료 목록에서도 제외한다. 명시적 재등록이나 장별 재생성은 허용한다. 제거한 PDF와 생성본의 출처 연결 및 프로젝트 파일 백업은 유지한다. 같은 엔진으로 재생성하는 것만으로 재현 품질이 개선되었다고 판정하지 않는다.
- 왼쪽 목록 아래의 분석 버튼은 PDF에서 ‘PDF 복원 분석’, 한글에서 ‘새 보고서 작성 분석’이다. 분석결과 보기와 PDF 한글보고서화를 함께 둔다. 원본 파일 등록만으로 자동 분석하지 않는다. PDF 한글화는 같은 원본·프로젝트의 복원 분석과 선택한 장이 있을 때 활성화하며 선택을 해제하면 비활성화한다. 생성본은 장별로 목록에 추가하며 생성한 HWPX의 작성 분석을 후속 단계로 자동 수행한다.
- 가운데 상단 자료 등록은 금회 측정·운영 PDF, BMT, PWV, 엑셀, CSV, 사진 등의 등록·목록 관리다. 전회 보고서 목록에 금회 측정 PDF를 자동 추가하지 않는다. 금회 자료 화면을 오가도 작업 보고서·원문 쪽을 유지한다.
- 가운데 PDF는 모든 페이지를 연속 스크롤로 읽는다. 제목 오른쪽의 페이지 바는 현재 보이는 쪽과 전체 쪽 수를 표시하고 번호 입력 후 Enter·이전/다음으로 이동한다. 제목과 페이지 바는 스크롤 중 상단에 유지한다. 선택 보고서 내려받기, 중앙 분석·작성 설정 버튼, 분석 전·PDF·원본 보존 상태줄, PDF 원문 라벨과 원문·복원 구조 대조 체크박스는 기본 화면에 두지 않는다. 설정은 오른쪽에 유지한다.
- 분석보기는 챕터별 요약을 먼저 보여주고 표 관리·그림 관리·문단 상세를 함께 제공한다. 작성 분석에서는 데이터의 내용 역할, 교체·재작성·유지·제외 결정과 금회 근거자료를 원문 위치에 연결한다. 복원 분석에서는 금회 작성 결정 대신 추출·보존과 대조할 근거를 보여준다. 분석은 후보이며 진단 판정이나 보고서 작성 완료가 아니다.
- 오른쪽은 분야·장, 분석 요약, 원문 PDF 연결, 역할별 글자 서식과 머리말·꼬리말·쪽 설정이다. HWPX에는 장 제목·중간/소제목·본문·표 제목·표 내용의 역할별 변경을 원본 공유 스타일 복제로 적용한다. 역할 분류와 실제 출력은 검토한다.

## 현재 연결과 한계

기본 화면은 `ReportPlatform.jsx`이며 `ReportStudio.jsx`의 기본 export를 통해 연다. 이전 작업의 서비스·보관 데이터와 회귀 검사용 `LegacyReportStudio`는 유지한다. 사용자 화면에 이전 폴더·목차 메뉴를 다시 노출하지 않는다.

`workflowAnalysis.js`는 원본 해시·프로젝트·분석 버전에 묶인 장/페이지·표·그림·문단/셀 후보를 구성한다. 내용 역할은 측정·운영 데이터, 분석·진단, 문제점·개선, 일반 관리, 현황·설명, 제목·캡션의 규칙 기반 후보다. 공학적 결론을 자동 확정한 것이 아니다. 원문 위치와 판단 근거를 확인하고 수동 보정한다.

`reportAnalyses`, `analysisReviews`, `reportMetadata`를 기존 프로젝트 책에 저장한다. 원본 파일은 기존 자료 저장소를 사용한다. 새 독립 DB나 사용자 전체 파일 목록으로 범위를 넓히지 않는다. 서식·금회 자료 반영 후보도 원문 PDF 연결을 상속한다. 프로젝트 파일을 다른 프로젝트로 복원하면 원본 해시는 유지하고 분석의 프로젝트 귀속을 새 대상으로 바꾼다.

PDF 원문은 분석 전에도 `PdfContinuousView.jsx`로 전체 쪽을 연속 배치하고 화면 가까이 있는 쪽만 렌더링한다. 전체 페이지의 크기를 읽어 공백 쪽·회전·용지 크기 차이도 배치에 반영한다. 스크롤 위치의 현재 쪽은 프로젝트에 저장하며 자료 탭·프로젝트 전환과 사이드바 너비 변경 뒤에도 보던 쪽을 유지한다. 프로젝트 작업 경로는 OCR을 쓰지 않는다. 공정·기계·공통·전기의 선택 페이지를 HWPX 참고 후보로 만들 수 있다. 원문에 없는 전기 장 제목·참고 안내·쪽 번호 배너를 본문에 넣지 않는다. 텍스트 이미지 조각은 OCR 없이 원문 그림 개체로 보존하며 편집 글자 확인이 필요하다고 표시한다. 임의 PDF의 글상자·벡터 도형 완전 복원, 본문 정밀 조판과 모든 공백 쪽의 실제 출력 검증은 아직 완료되지 않았다.

HWPX 구조 미리보기의 쪽 경계는 실제 한글 조판이 아니다. 연결한 PDF에서는 실제 원문 쪽을 대조할 수 있다. 한글화 후보를 완료본으로 표시하지 않고, 후보 HWPX의 독립 출력과 원문을 비교해 재현 범위를 확인한다.

2026-11-03 흐림·중복 보정: `cropPdfPictures`라는 기존 API 이름은 유지하지만 전체 PDF 화면을 잘라 그림을 만들지 않는다. PDF.js의 원래 이미지 개체와 변환행렬에서 픽셀을 꺼낸다. 그림 위의 편집 글자가 이미지에 함께 찍히면 안 된다. 원문 글자와 겹친 그림 및 인접 타일 배경은 글 뒤의 PAPER 좌표 개체로 보존한다. 장 구분 표지는 추출 baseline·x 좌표와 고정 줄 높이로 배치하며, 첫 장 표지에 임의 머리말·꼬리말·쪽 번호를 보이지 않는다. 일반 본문은 아직 흐름식 재구성이며 동일 조판 완료가 아니다. 식별 가능한 PDF 글꼴 이름과 원문 글자 크기·용지 크기·표 너비를 유지하고, 불명확한 글꼴은 경고로 남긴다. `pdf-structure/2`에서 실제 글꼴 이름과 표 셀 서체를 새로 추출하므로 이전 분석을 사용하는 보고서는 다시 분석한다. 미리보기 SVG의 고유 픽셀 크기는 표시 너비·화면 배율을 따르며 문서의 viewBox·텍스트·SHA는 바꾸지 않는다.
